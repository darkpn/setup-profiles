# setup-ws_tls.sh

Интерактивный установщик origin-ноды для схемы **VLESS → WebSocket + TLS → relay**.

## Запуск

Перед запуском создайте A-запись домена на IP сервера, затем выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/darkpn/setup-profiles/main/setup-ws_tls.sh \
  -o /tmp/setup-ws_tls.sh && sudo bash /tmp/setup-ws_tls.sh
```

## Опции

| Опция | Действие |
|---|---|
| `--status` | показать сохранённое состояние и прогнать проверки, ничего не меняя |
| `--skip-listener-check` | не ждать появления listener Xray |
| `-y`, `--assume-yes` | отвечать «да» на все подтверждения |
| `--no-color` | отключить цвет (также действует `NO_COLOR=1`) |
| `--version` | версия скрипта |

## Параметры

Перед вводом домена скрипт определяет публичный IPv4 сервера и показывает
готовую DNS-инструкцию, затем ждёт распространения A-записи (до 5 минут,
с прогресс-баром) и только потом продолжает. Используйте прямую DNS-запись без
CDN/прокси; если IPv6 не настроен, скрипт предупредит о конфликтующей
AAAA-записи.

Скрипт последовательно запросит:

| Параметр | По умолчанию | Пример |
|---|---:|---|
| Домен origin | — | `origin.example.com` |
| Уникальный WS-путь | — | `/assets/RandomPath` |
| TLS-порт | `443` | `443` или `8443` |
| Локальный WS-порт Xray | `18083` | `18083` |
| IP relay | — | IP-адрес relay-сервера |

Значения сохраняются в `/root/.ws-node-setup.conf` и подставляются при следующем
запуске. Состояние пишется до долгих проверок, поэтому даже прерванный запуск
не потребует вводить всё заново.

## Что выполняется

- проверка ОС, ядра, виртуализации, синхронизации времени, места на диске;
- ожидание корректной A-записи, проверка конфликтующей AAAA;
- включение **BBR** (`tcp_bbr` + `fq`) и сетевой тюнинг, включая UDP-буферы под
  HTTP/3 и `LimitNOFILE` для Caddy — всё закрепляется в `/etc/sysctl.d/`;
- отображение RAM/swap и предложение создать swap 2 ГБ;
- проверка занятости 80/443 и TLS-порта с определением процесса-владельца;
- предупреждение о посторонних портах, открытых наружу;
- установка и настройка Caddy, выпуск TLS-сертификата;
- настройка HTTPS, `/healthz` и WebSocket reverse proxy;
- опциональная установка и включение UFW (SSH разрешается первым правилом);
- генерация JSON inbound и инструкции по его добавлению в Config Profile;
- ожидание появления listener после применения профиля;
- проверки: listener, **прямой WS-апгрейд к Xray в обход Caddy**, HTTPS `200`,
  WebSocket `101`, маскировочная страница, срок действия сертификата.

Config Profile в Remnawave скрипт не изменяет: новый inbound добавляется в
существующий массив `inbounds` вручную. Инструкция — в
`/root/ws-node-generated/inbound-merge-instructions.txt`.

### О TLS-порте 443

Если TLS-порт равен `443`, маскировочный сайт и WebSocket обслуживаются **одним**
site-блоком, где статика стоит последним fallback-ом. Два отдельных блока на
одном `host:port` Caddy сливает в один маршрут, и `file_server` без path-матчера
перехватывает всё — `/healthz` и WS-путь начинают отдавать `404`. При TLS-порте,
отличном от `443`, генерируются два блока: маскировочный сайт на 80/443 и WS на
выбранном порту.

Побочное следствие: при порте `443` ограничить доступ только по IP relay нельзя —
порт нужен и маскировочному сайту. Для ограничения по IP используйте отдельный
порт, например `8443`.

## Проверка результата

Успешный запуск завершается результатами:

```text
✔ listener Xray: 127.0.0.1:18083
✔ Xray напрямую отвечает 101 на /assets/RandomPath
✔ HTTPS /healthz → 200
✔ WebSocket через TLS → 101
```

Прямая проверка Xray в обход Caddy разделяет два разных класса проблем: если она
даёт `101`, а через TLS приходит `404`, дело в Caddy; если она сама не даёт
`101` — не совпадает `path` или `port` в применённом Config Profile.

Код `3` означает, что конфигурация создана, но проверки прошли не полностью.
Быстро перепроверить состояние без изменений:

```bash
sudo /path/to/setup-ws_tls.sh --status
```

## Повторный запуск и восстановление

Скрипт идемпотентен: повторный запуск безопасен и подставляет прошлые ответы.
Перед изменениями создаётся новый backup. Для восстановления Caddyfile:

```bash
sudo /root/ws-node-backup-YYYYMMDD-HHMMSS/restore.sh
```

## Требования

- Ubuntu или Debian;
- root-доступ;
- домен с A-записью на сервер;
- установленная RemnaNode;
- доступ к пакетным репозиториям и Let's Encrypt.
